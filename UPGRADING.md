# Upgrade to NVL Light

Target PHP 8.4, Laravel 13, Testbench 11 for development, and native NVL Activity storage. NVL Light uses major 7 and ships an optional Spatie v5 capture adapter without requiring the Spatie package.

- Remove Spatie's `LogsActivity` before enabling native capture on a model. A model that uses both traits now fails at boot, whatever its capture options.
- Remove Spatie logger calls/traits and `adoption.spatie` configuration. Replace `logOptions()` with `captureOptions(): ActivityCaptureOptions`; declare explicit capture fields and lifecycle events. Register every event policy under `nvl-activity.events` before first use. Unknown events fail; minimum retention and audience policies now apply in native services.
- Store diffs in `attribute_changes`. Complete the Spatie v5 data layout before using the reviewed [Activity schema adoption](README.md#adopt-a-spatie-v5-table) workflow for an existing table. Fresh native migrations include both JSON columns and microsecond timestamps.
- Adoption runs through nvl:adopt with reviewed, checkpointed batches and an explicit activate step. Committed batches survive a failure. Keep writers stopped until verify and activate pass. Enable `nvl-core.adoption.migrations.enabled` and migrate; when Activity uses its own connection, migrate the core adoption tables on that connection too (`php artisan migrate --database=<activity connection> --path=vendor/nvl/core/support/database/migrations`, so only the adoption tables run there). Then run `php artisan nvl:adopt activity plan`, `apply --fingerprint=…` (resume with `--run=…`), `verify` and `activate --fingerprint=…`. The manifest takes no options. `ActivitySchemaAdopter` remains available and unchanged.
- Use `ActivityRecorder::record($entry, $actor)` or `PositionalActivityRecorder` for a staged facade migration. Actors are required persisted authenticatables or explicitly authorized `SystemActor::Background`. Resolve legacy operator references through the host actor resolver. Scalar historical attribution belongs in immutable envelopes. Blank events and unknown/protected fields fail.
- Bind `ActivityAuthorization`. Replace HTTP gates with this native host policy plus consumer-owned transport authorization.
- Native capture now records a `restored` fact with `attributes` only and an empty `old`, as Spatie v5 does. Readers that compared a restore's `old` values should use `attributes`.
- Wrap mapped model mutations in `ActivityCaptureContext::run($actor, $operation)`. Preserve a host transaction when model/audit writes must roll back together. Unmapped models remain silent.
- Replace `ActivityReadService`, listing/causer Actions and read contracts with `ActivityReader::paginate`, `timeline`, `causers`. Use native models, collections and paginators. Map consumer DTOs explicitly.
- Replace `ModelActivityTimelineService`, `MergesActivityTimeline`, `ActivityTimelineData`, `MergesActivity`, `MergeableActivityData` and `TranslatesToActivity` presentation composition with native `ActivityTimelineSource` queries. Timelines now have explicit finite limits.
- Map native models and semantic headline parts into the host's own data, timeline segments, routes and response envelopes.
- Replace `QueueActivityLogPurgeAction` with `ActivityPurgeDispatcher::dispatch($criteria, $actor)`. Replace old tenancy envelopes/worklists with native Ownership scopes and captured jobs. Old suffix event alias `ActivityLogPurgeQueuedEvent` is removed; subscribe to `ActivityLogPurgeQueued`.
- Remove `routes`, `authorization.abilities` and `tenancy` package configuration. No legacy aliases or automatic bridge authority remain. Own routes and response codes at the host boundary.
- `ActivityRecordEnvelope`, `ActivitySubjectReference` and `ActivityCauserReference` retain real immutable delivery/reference semantics. Replay checks operate on complete facts; redaction changes storage values without allowing conflicting deliveries to reuse an ID.
- Activity timestamps were stored in the application timezone from 7.0.2 until the Unreleased change to UTC below. On an application whose timezone is not UTC, envelope facts recorded before 7.0.2 keep their earlier UTC wall clock.
- Run `php artisan migrate`: on PostgreSQL the new `2026_11_11_000000_nvl_activity_add_newest_first_index` migration adds the `created_at DESC NULLS LAST, id DESC` index newest-first reads use; it does nothing on other drivers. Hosts owning published migrations add the same index, which `nvl:activity:doctor` reports under `schema.indexes`.
- Remove `causer_suggestions.label_attribute`, `causer_suggestions.sublabel_attribute` and `retention.external_visibility_timeout_seconds` from a published configuration file; nothing reads them. For a queue driver without `retry_after` such as SQS, declare the queue's visibility timeout as `retry_after` on the connection so `nvl:activity:doctor` can verify it exceeds the purge timeout.
- `causer_suggestions.scan_limit` now bounds the number of most recent attributed facts scanned for suggestions, not the number of distinct causers.
- `PurgeActivityLogsJob` deletes at most 10,000 rows per run and dispatches a continuation; keep a worker on the purge queue until the purge completes. `CauserNormalizer`, `TimelineFilter::deduplicateByTimestamp()` and the provider's `provides()` list are removed.
- Automatic redaction now matches whole key segments: `token`, `api_token`, `accessToken` and `password_hash` are redacted, while `token_count`, `authorization_status` and `secretary_id` are stored. Declare any other sensitive field in the event policy's `redacted_fields`.

Drain obsolete queued payloads and restart workers before deploying changed contracts. No migration rewrites historical audit rows or transfers their owner. Review historical credentials separately; new recording redacts credential keys.

## Unreleased

- Activity `created_at` and `updated_at` are now stored as UTC instants and read back as UTC `Carbon` instances. Earlier releases stored the application-timezone wall clock, which repeats inside a daylight-saving overlap. Hosts whose `app.timezone` has always been `UTC` need no data change. Any other host must convert existing rows once, including tables adopted from Spatie, during a write freeze (stop workers that deliver activity envelopes) and before serving the new release, using the timezone the rows were written under. On PostgreSQL (`timestamp(6) without time zone`):

  ```sql
  UPDATE nvl_activity_log
  SET created_at = (created_at AT TIME ZONE 'Europe/Sofia') AT TIME ZONE 'UTC',
      updated_at = (updated_at AT TIME ZONE 'Europe/Sofia') AT TIME ZONE 'UTC';
  ```

  On SQLite, read each raw value, parse it with `Carbon::parse($raw, $timezone)` and write `->utc()->format('Y-m-d H:i:s.u')`. Substitute your configured table name and timezone. Envelope facts that 7.0.0–7.0.1 stored as a UTC wall clock are already UTC: convert only rows written by later releases, or skip envelope rows whose `properties->occurred_at` already matches `created_at` in UTC. A wall clock written inside a daylight-saving overlap was already ambiguous; the conversion picks one offset, so review facts recorded in that hour. Code that formats these attributes without `->setTimezone(...)` now sees UTC values; the instants are unchanged. Retrying an envelope stored with the application-timezone wall clock is still recognised as the same fact. Opaque `cursor()` tokens issued before the upgrade should be discarded.
- Activity schema adoption converts PostgreSQL `uuid` morph ids (`subject_id`, `causer_id`) to `varchar(255)` in a new `morph_ids` step; the conversion rewrites the table under its lock. The adapter version changes to 2, so an unfinished `nvl:adopt activity` run planned with 7.2.0 is refused: abandon the unfinished 7.2.0 run with `nvl:adopt activity abandon --run=<id>`, then plan and apply again. Activated runs are unaffected. On PostgreSQL an `ActivitySchemaAdopter` fingerprint reviewed with 7.2.0 also changes. A table already activated with `uuid` morph ids keeps them; convert them with `ALTER TABLE … ALTER COLUMN subject_id TYPE varchar(255) USING subject_id::text` (and `causer_id`) before using `whereHas('activitiesAsSubject')`.
- Plans returned by `ActivitySchemaAdopter` contain a `widen_morph_ids` list.
- `new ActivityPurgeCriteria(...)` throws `ActivityPurgeCriteriaException` for invalid criteria: neither or both of `days` and `before`, non-positive days, an unparseable date, or `after` not earlier than the cutoff.
- Causer suggestions omit causers known only from facts the actor may not read.
- Service reads return soft-deleted subjects when `nvl-activity.reads.include_soft_deleted_subjects` is true; previously only the model relation honoured it.
- Activity search now uses Core's `TextMatcher` binding; a host that rebinds it changes Activity search too.
